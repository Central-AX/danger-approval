# danger-approval（危険な承認を赤くする）

Claude Code の承認ダイアログは、ファイルを1つ読むだけの操作でも、削除や外部送信でも、同じ見た目で出ます。慣れてくると中身を読まずに許可してしまいがちです。

このmodは、危険な操作のときだけ画面を赤くして、「いまのは読んでから押すやつ」だと気づけるようにします。許可・拒否の判定そのものには手を入れません。目立たせるだけです。

## 入れ方

Claude Code のターミナルのセッションで、入力欄に次の1行を打ちます。途中で `y`（マーケットプレイスの追加）と、入れる範囲を聞かれます。

```
/plugin install danger-approval --marketplace Central-AX/danger-approval
```

シェルから入れる場合はこちらです。

```
claude plugin install danger-approval --marketplace Central-AX/danger-approval
```

Claude Code 2.1.330 と、そのデスクトップアプリで動作を確認しています。古いバージョンでは読み込めないことがあります。

## 出るもの

| 場面 | 表示 |
|---|---|
| 危険な操作で承認を求められた | 入力欄の上に明るい赤の帯「⚠ 危険な承認：削除 ｜ rm …」。タイトルが「⚠ 危険な承認」の通知。環境によっては承認ダイアログの下に注意の1行 |
| 危険な操作が承認なしで自動実行された（自動モードなど） | 右上に10秒のトースト。入力欄の上に暗い赤の帯「⚠ 自動で実行された危険な操作 N件」。次にメッセージを送るまで残る |
| ふつうの操作 | 何も出ない |

## 「危険」に入っているもの

- 削除：`rm`、`Remove-Item`、`del`、各種ツールの delete / trash
- git：`git push`、強制push、`reset --hard`、`clean`、`branch -D`、`gh pr merge`
- 外部への送信：メール・チャットの送信、返信、転送、予約投稿
- 共有設定の変更：ファイル共有など
- 会計ソフトへの書き込み：freee の読み取り以外
- 本番への反映：`wrangler deploy`、`vercel --prod`、`npm run deploy`、`clasp push`
- その他：データベースの削除系SQL、ドメイン購入、PCのシャットダウン

## 自分の環境に合わせる

`hooks/register.tsx` の冒頭にある2つの表を直します。

- `COMMAND_RULES`：シェル（Bash / PowerShell）のコマンドに対する判定
- `TOOL_RULES`：MCPツールなどのツール名（最後の `__` より後ろ）に対する判定

どちらも `[正規表現, 帯に出す名前]` の組です。上から順に見て、最初に当たったものを使います。

## 制限

- 承認ダイアログそのものの色は変えられません（Claude Code の仕様）。赤くなるのは、入力欄の上の帯と通知です。
- 通知の色はOS側の表示なので変わりません。変わるのはタイトルと本文です。
- 危険の判定はコマンドの文字列とツール名の照合です。スクリプトの中で削除している場合などは拾えません。安全装置ではなく、注意を引くための表示として使ってください。
